## 二、架构决策记录（ADR）

### ADR-1：引擎持有方式 = 枚举 + trait 契约双轨

**决策**：`Database` 持有 `HashMap<u32, EngineTable>`（枚举变体 = 各引擎具体类型），分派 match 集中在 `EngineTable` impl；同步定义 `StorageEngine` trait 作为接口契约（文档化交付物），由各引擎结构体实现。

**理由**：
- Table 有 20+ 具体方法（含 create_vector_index / add_fts_index 等专属能力），trait 对象方案必然引入 `as_any().downcast` 反模式（运行期失败、丢编译期保证）
- 枚举 match 静态分派：类型安全、零虚调用开销、编译器驱动改造
- 本库仅 3 个内置引擎、无第三方插件生态诉求，"新增引擎改枚举"的劣势不成立
- trait 契约保留架构图抽象层，未来第 4 个引擎可先实现 trait 再进枚举

**接口**（trait 契约，对齐文档 v1.0）：

```rust
pub trait StorageEngine {
    fn engine_type(&self) -> EngineType;
    // DDL
    fn create_table(&mut self, table_id: u64, schema: &TableSchema) -> Result<()>;
    fn drop_table(&mut self, table_id: u64) -> Result<()>;
    // DML
    fn insert(&mut self, table_id: u64, rows: DataChunk) -> Result<usize>;
    fn update(&mut self, table_id: u64, pk: &Value, updates: &[(usize, Value)]) -> Result<bool>;
    fn delete(&mut self, table_id: u64, pk: &Value) -> Result<bool>;
    // Query
    fn scan(&mut self, table_id: u64, spec: &ScanSpec) -> Result<Vec<DataChunk>>;
    // 事务
    fn begin_txn(&mut self, txn_id: u64) -> Result<()>;
    fn commit_txn(&mut self, txn_id: u64) -> Result<()>;
    fn abort_txn(&mut self, txn_id: u64) -> Result<()>;
}
```

### ADR-2：MemoryEngine 复用现有事务管线

**决策**：内存表走现有 `txn_manager` MVCC（ApplyOp 已引擎无关，txn/mod.rs:62）+ `apply_to_storage`（insert.rs:130）按引擎分派；无持久化模式下事务提交跳过 WAL 落盘。

**理由**：零新 MVCC 代码、功能完整、M4 跨引擎事务天然就绪。文档 M2-5 的"简化版独立 MVCC"重复实现版本链，性价比低。

### ADR-3：磁盘格式向后兼容

- `TableDef` 加 `engine: EngineType` 字段，`#[serde(default)]` → 旧文件读为 Columnar，零迁移
- `ENGINE` 子句解析照抄 `strip_using_hnsw` 模式（parser.rs:394）：先剥后喂 sqlparser，AST 加 engine 字段
- WAL 记录加 engine_type（19→20 字节头，wal/mod.rs:67）：旧 WAL 不兼容可接受（恢复依赖 checkpoint 段，recovery.rs 目前只统计不重放，M4 一并补全重放）

## 三、执行阶段

### P0 — M1 验收复测（已完成 ✅）

复测发现 ORDER BY/GROUP BY 未达标（50.17ms / 6.83ms），根因是执行器
「行→列→行」双重转置（M1-3）。已修复并全部达标：

| 标准 | 修复前 | 修复后 | 目标 | 判定 |
|---|---|---|---|---|
| 10 万行 WHERE 1% 选择性 | 494µs | 877µs | < 5ms | ✅ |
| 10 万行 ORDER BY 整数列 | 50.17ms | 22.7ms | < 30ms | ✅ |
| 10 万行单列整数 GROUP BY | 6.83ms | 3.91ms | < 5ms | ✅ |

**本轮交付**（commit "perf(executor): M1 验收达标"）：
- M1-3 转置消除：`try_execute_chunks` 列式递归执行器（读链全程 Typed，
  仅最终物化一次），Sort/Aggregate/Filter 分支接入
- M1-6 Zone Map：ColumnStore::estimate_skip + scan_to_chunks_with_skip
  batch 级 PREWHERE 筛选（含 Delta 层行级筛选）
- 附带修复：Aggregate 分支列名 bug、多 batch 相对索引 gather、Delta 谓词缺失
- 收益：B-4 1.82x → 0.71x（首次击败 SQLite）；786+5+8 全绿

M2 加 Memory 变体时枚举 match 编译器强制覆盖所有分派点。

## 四、风险控制

- 每阶段独立 commit + 全量回归（786+5+8 基线）+ A 系列基准对比
- P1 架构改造完成后先整体验收再进新引擎
- 磁盘格式改动一律 `#[serde(default)]` 向后兼容；WAL 格式变更单独评估（ADR-3）
- 专属能力（索引/向量/FTS/alter/pragma）仅 Columnar 变体支持，其他引擎返回清晰错误
