# Phase 1.6 — M06 UPSERT (INSERT...ON CONFLICT)

## Summary

Implemented `INSERT...ON CONFLICT DO UPDATE/NOTHING` (UPSERT) syntax, allowing inserts to gracefully handle unique constraint violations by either updating existing rows or silently skipping conflicts.

## Changes

### Parser (`src/sql/parser.rs`)

- Parses `ON CONFLICT` clause from sqlparser's `Insert.on` field
- Extracts `ConflictTarget::Columns` → conflict column names
- Extracts `OnConflictAction::DoNothing` / `DoUpdate` with assignments
- Populates `InsertStmt.on_conflict: Option<OnConflictClause>`

### Physical Plan (`src/executor/physical_plan.rs`)

- Added `on_conflict: Option<crate::sql::ast::OnConflictClause>` field to `PhysicalPlan::Insert`

### Planner (`src/sql/planner.rs`)

- `plan_insert` passes `stmt.on_conflict` through to `PhysicalPlan::Insert`

### Executor (`src/executor/executor.rs`)

- `execute_upsert` function handles the full UPSERT logic:
  1. For each row, find conflicting row via `find_conflicting_row` (index-based, see below)
  2. If conflict found + `DO NOTHING` → skip
  3. If conflict found + `DO UPDATE` → apply SET assignments to existing row
  4. If no conflict → normal insert
- Supports RETURNING clause with UPSERT
- Uses `evaluate_returning_expr` for column references in SET assignments

### `find_conflicting_row` — 索引优先的冲突行查找

**查找优先级（避免 O(n) 全表扫描）：**

1. **主键索引（BTreeMap, O(log n)）** — 单列冲突且该列是 PK 时，通过 `lookup_primary_key` 直接定位
2. **唯一二级索引（SkipList, O(log n)）** — 单列冲突且存在匹配的唯一索引时，通过 `index.get(key)` 直接定位
3. **全表扫描（O(n)）** — 兜底（多列冲突或无可匹配索引）

## Tests

- `test_upsert_do_update`: INSERT with ON CONFLICT DO UPDATE SET, verifies row is updated
- `test_upsert_do_nothing`: INSERT with ON CONFLICT DO NOTHING, verifies original row unchanged
