## 4. 关键变化解读

1. **引擎基础路径线性无退化**：A 裸存三指标随文本量（9.5×）近似线性
   （9.6-10.2×）——批量插入/checkpoint/扫描框架无规模瓶颈。
   行均耗时随行数规模摊销固定开销而降（批量 2048 行路径、WAL 组提交）。

2. **压缩臂每 MB 成本上升 40-50%**（大数据）：
   - zstd 压缩吞吐 263MB/s → 189MB/s（-28%）：混合语料高熵（工具输出/
     日志）压缩慢
   - 行均文本 3.39KB → 1.32KB：短文本放大块级固定开销（列解析、块头）
   - 读回 +44%：同一原因（解压慢 + 行级开销大）

3. **zstd 先行调度在 20× 数据量下验证成立**：C1/C2/C3（TD 配置）在大数据
   下磁盘 255.47MB == B、checkpoint 5.5s ≈ B 5.44s——正式文本块 zstd 恒
   达标直选，TD 难块兜底不参与，TD 配置与 zstd 完全同速同体积。

4. **D 臂（FTS）插入是固有成本**：49.45s vs 无索引 1.5s（33×）——FTS 索引
   构建 tokenize 是插入路径固有开销（非压缩开销）；checkpoint 6.29s 与
   无索引 5.44s 差异小（缓存共享让 TD 兜底块免二次 tokenize）。

5. **压缩臂相对裸存的 checkpoint 倍率**：小数据 0.41/0.21 ≈ 1.9×、
   大数据 5.44/2.02 ≈ 2.7×——高熵 + 短文本使压缩成本相对上升。

## 6. 结论

- 大数据量下无超线性退化：核心路径线性，压缩臂高熵成本可预期
  （+40-50%/MB）
- zstd 先行调度与 FTS 缓存共享在大数据量验证稳定（C==B、D checkpoint
  近 B）
- 后续优化方向（若需）：高熵块压缩（zstd level 自适应）、FTS 插入
  tokenize 批量化

## 7. FTS 插入路径优化（v0.21.2，D 臂 49.45s → 9.01s，-82%）

profiling（bench_fts_insert，混合语料三档扫描）：tokenize 占插入路径
84-86%（36ms/MB，混合语料为纯自然语言 2.5×）——postings push 仅
1.7-4.1%，且三档每 MB 成本恒定（42.5/42.5/43.1ms/MB）**无超线性**
（此前 33.1→48ms/MB 增长实为行均文本 3.39KB→1.32KB 的数据分布差异，
短文本放大每行固定开销）。

实施：
1. table.rs 批量插入路径行×列级 rayon 并行 tokenize（profiling 结论：
   85% 成本命中）+ 并行 prepare（tf 聚合/空白过滤/排序，拆自
   add_document_with_tokens，逻辑逐字节一致）
2. sparse.rs：add_document_with_tokens 拆 prepare_document（并行段，
   static）+ add_document_prepared（主线程串行 push）
3. 缓存填充批量持锁（消除每行 Mutex lock）

结果（779,298 行 / 1,030MB，六臂逐行一致 ✓）：

| 阶段 | 插入 | vs 无索引 |
|---|---|---|
| 优化前 | 49.45s | 33× |
| 并行 tokenize | 12.74s | 8.5× |
| + prepare 并行 | 9.34s | 6.2× |
| + 批量缓存锁 | **9.01s** | 6.0×（FTS 固有成本） |

剩余构成：列存 1.5s + postings push 串行 ~1.8s + 并行残余 + 缓存填充
（TD 场景）。索引构建固有成本已接近下限（tokenize 并行后 ~2s）。

### 7.1 再优化：postings 定长槽数组（D 臂 9.01s → 8.72s）

分片锁方案实测**损坏回退**（并行 push 行号乱序 → delta 下溢，release
无 debug_assert 防护，FTS 索引损坏——磁盘 +61MB 佐证；读回校验不查
索引故假通过）。encode_batch（行序收集 + 并行编码 + 跨批 append）实测
无收益（批间 overhead 抵消；append 曾 O(n²) 复制，改 in-place extend
后持平）。

正确落地：postings 改**定长槽数组** `Vec<Option<CompressedPostings>>`
（0x10000 槽，512KB）——entry 查询从 FxHashMap 哈希（~47ns/对）变
数组索引（~15ns/对）；行序仍由主线程循环保证；to_bytes 非空槽 id
升序确定序（zstd 压缩微赢：343.10 → 341.97MB）。

结果：插入 8.72s（基线 49.45s，-82.4%）；磁盘/checkpoint/读回正常；
六臂逐行一致 ✓；全量回归 EXIT 0。
