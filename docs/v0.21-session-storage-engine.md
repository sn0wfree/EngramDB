# v0.21 会话存储引擎（定稿：Engram 统一 Token 流压缩）

> 日期：2026-08-07（定稿版，取代早期草稿）
> 目标：Agent 会话内容存储——**业务 API 无感**（opencode 式调用），
> 引擎层消除冗余：写放大 610× → ~1×、体积可控、零维护（TTL 自动清）。
> 核心：统一 Token 流压缩（见 docs/engram-token-stream-compression.md）
> 依据：docs/opencode-sqlite-storage-analysis.md（opencode 实态 + 源码）

---

## 一、定稿架构

```
业务层（无感，opencode 式 API）:
  SessionStore::begin_message / append_part(全量快照) / update_part / finish_message
              / get_session / recent_messages / search_messages

引擎层（透明）:
  event_log（Log 引擎）:  完整事件流（全量快照），content 列分词+delta 压缩 → 审计/回放/重建
  sessions / messages（Columnar）: 聚合物化（finish 时单事务投影）→ 读取/分析/计费/搜索
```

**设计原则**（用户确认）：
- 业务照旧：opencode 怎么写我们就怎么写（全量快照事件），用法无感
- 引擎消除冗余：分词压缩把快照流冗余压到 ~1×；Log 快写 + TTL 零维护
- 审计/回放为 nice-to-have（event_log 完整记录，回放重建后续实现）

## 二、表结构

```sql
-- 事件流（Log，append-only，content 分词压缩）
event_log (
    session_id VARCHAR NOT NULL,
    msg_id     VARCHAR NOT NULL,
    seq        INT NOT NULL,
    event_type VARCHAR NOT NULL,   -- message.updated / part.updated / step / tool / finish
    content    VARCHAR NOT NULL,   -- 全量快照（TokenDelta 压缩，Varchar 列）
    metadata   JSON,               -- cost/tokens/model（小数据，不压缩）
    created    TIMESTAMP NOT NULL
) ENGINE = Log WITH TTL 7d;

-- 聚合（Columnar，finish 时一次写）
sessions (
    session_id VARCHAR PRIMARY KEY, agent VARCHAR, model VARCHAR,
    cost REAL, tokens_* INT..., created TIMESTAMP, updated TIMESTAMP
) ENGINE = Columnar;

messages (
    msg_id VARCHAR PRIMARY KEY, session_id VARCHAR, role VARCHAR,
    content VARCHAR, parts JSON, model VARCHAR, tokens INT,
    created TIMESTAMP, updated TIMESTAMP, is_deleted BOOLEAN
) ENGINE = Columnar;  -- 长期保留
```

## 三、写入路径（业务无感 + 引擎透明压缩）

```
append_part(msg, type, "全文快照")     ← 业务与 opencode 完全一致
  → 引擎：分词（TokenStream）→ 块级字典 + 前缀 delta → Log 落盘（微秒级）

finish_message(msg)                    ← 业务同款
  → 单事务：Log finish 事件 + Columnar 聚合写入（messages + sessions 计费累计）
```

- 写放大：事件流块内 delta → 610 次更新 ≈ 只存 610 次新增 token（~1×）
- 崩溃语义：未完成消息在 Log（事件完整），物化缺失 → TTL 兜底 + 后续回放重建（nice-to-have）

## 三·五、检索 × 压缩 路径矩阵（搜索字段永不被 token 化到不可搜）

**原则**：压缩是存储层透明行为，查询层永远看到原文；检索主路径走独立索引。

| 字段 | 存储形态 | 检索路径 | 说明 |
|---|---|---|---|
| `event_log.content` | TokenDelta 压缩 | **不提供 LIKE** | 审计/回放专用（TTL 7d），回放时块解压 |
| `messages.content` | 压缩存储（透明）| **LIKE**：解压候选块 → 逐行匹配（min/max + 布隆剪枝先行，column_store.rs:1214/1240）；**FTS**：倒排索引（norm token，P0-7 后中文可搜）| LIKE 语义与原文列完全一致（执行器操作解压后 Value）；FTS 是推荐主路径 |
| `messages.parts`（JSON）| 不压缩（Json 类型）| LIKE / 表达式 | 现有行为不变 |
| `sessions.*` | 常规 | 主键 / 范围（min/max 剪枝）| 现有行为不变 |

**双保底**：① 解压透明性——LIKE 在压缩列上语义不变（引擎内部解压候选块）；② 独立索引——FTS 倒排（token 化后**更强**：中文可搜、词级匹配），与压缩字节完全解耦。
**列级可控**：`compress()` 按类型/列分派（compression/mod.rs:32），高频 LIKE 热点列可配置不压缩（best-of 自动退化已有）。
