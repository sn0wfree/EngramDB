# v0.16 性能优化路线图

> 规划日期：2026-08-05
> 对标基线：SQLite 3.45（A 系列验收基准，`benches/v0_13_acceptance_bench.rs`）
> 状态：S1 速赢 5 项已完成 ✅（2026-08-05），S2/S3 为方向性规划

---

## 一、总体策略

三阶段递进：

| 阶段 | 主题 | 工期 | 预期收益 | 风险 |
|---|---|---|---|---|
| S1 | 独立速赢（Radix / 整数键 / 表达式特化 / Delta 区间 / 扫描零克隆） | 1-3 天 | 1.5-5x（局部） | 低（每项独立 commit + 回归） |
| S2 | ColumnData 类型化列重构（渐进式双路径） | 2-4 周 | 3-10x（读路径全面） | 高（语义复刻，等价性测试兜底） |
| S3 | 大数据量质变算法（外排序 / Grace Join / Zone Map / Bloom Filter / 延迟物化） | 长期 | 超内存场景从 OOM → 可执行 | 中（依赖 S2 落地） |

**核心洞察**：最大的性能瓶颈是 `Value` enum 的 tag 间接层（32B/值，破坏内存连续性，阻止 SIMD 自动向量化）。S2 是"地基"，S1 是地基之前的独立速赢。

**S1 完成情况（2026-08-05）**：

| 项 | commit | 实测收益 |
|---|---|---|
| S1.1 Radix Sort | `perf(sort): 单列整数 Radix Sort` | 排序核心 1M 行 radix 56.6ms vs sort_by 273.1ms = **4.8x**；全链路 B-4 1.42x（瓶颈在行式物化） |
| S1.2 Group By 整数键 | `perf(aggregate): GROUP BY 单列整数键直连` | 1M 行 1000 组 int_key 32.2ms vs vec_key 39.2ms = **1.22x**（瓶颈在 accumulate 的 Value match） |
| S1.3 表达式特化 | `perf(expr): 二元表达式类型特化快速路径` | Varchar 比较 1M 行 **1.47x**（消除 to_flat 深拷贝）；Int64 持平（to_flat 便宜） |
| S1.4 Delta 区间 | `perf(delta): 连续 rowid 区间映射` | 批量插入省 N 次哈希插入（insert_batch 1000 行：1 条区间 vs 1000 次 insert） |
| S1.5 扫描零克隆 | `perf(scan): drain 零拷贝移动` | Varchar/Blob 列免深拷贝；A 系列无回归 |

S1 顺带修复 2 个既有 bug：value_cmp 缺 Timestamp 分支（排序/比较失效）（sort.rs + expression.rs 两处）。

**S1 结论**：5 项速赢独立收益 1.2-4.8x，但全链路收益受限于行式物化与 Value 层开销——量级收益需 S2 ColumnData 兑现（微基准已证实瓶颈在 accumulate/get/to_rows 的 Value match 与深拷贝，而非算法本身）。

**已确认的 S2 设计决策**：
1. 渐进式双路径：`Vector` 新增 `Typed(ColumnData)` variant，与 `Flat(Vec<Value>)` 并存，逐算子迁移
2. 执行器 + 存储层全链路：`ColumnChunk` 内存态也改 `ColumnData`，`read_column` 直接产出类型化数组
3. Hash 键优化随 S2 一起落地（单列整数键 `FxHashMap<i64, …>`）

## 三、S1：独立速赢（优先执行）

### S1.1 Radix Sort 整数列排序

- 现状：sort.rs:24-28 转行式 `Vec<Vec<Value>>` → `sort_by(cmp_rows)`（O(N log N) + 逐元素 Value match）
- 改法：sort_keys 单列且列元素为 Int32/Int64/Timestamp → 提取 `Vec<i64>`（null 标记位），LSD Radix（4-pass 8bit），产出稳定排序索引后按索引重排行；DESC 反向、NULL 最前（与 `value_cmp` 语义一致）；Top-N 场景保留现有堆（堆本就 O(N log k)）
- 语义注意：Rust `sort_by` 稳定，LSD radix 天然稳定 → 多列排序行为不变
- 文件：`src/executor/operators/sort.rs`（~100 行）
- 验证：sort 测试 + A-3 bench（当前 0.01x）+ 新增百万行微基准
- 预期：单列整数排序 3-5x，Top-N 2-3x

### S1.2 Group By 单列整数键直连

- 现状：`FxHashMap<Vec<Value>, Vec<PartialAggState>>`（aggregate.rs:279/405）——hash 遍历 + enum match + 堆分配
- 改法：`group_by.len()==1` 且列为 Int32/Int64/Boolean/Timestamp → `FxHashMap<i64, Vec<PartialAggState>>`；**NULL 键语义保留**（现有 NULL 也是一个 key）；partial 合并表（:436）同步整数路径
- 文件：`src/executor/operators/aggregate.rs`（~80 行）
- 验证：Group By 测试 + A-1 bench（当前 2.64x）+ 新微基准
- 预期：单列整数 Group By 5-10x

### S1.3 表达式同类型特化 + SIMD

- 现状：`eval_binary_vectorized`（expression.rs:144-155）逐元素 `eval_binary_pair`（双重 enum match）
- 改法：一般路径前加特化检测：双 Flat 且同类型数值（Int64/Int32/Float64/Float32）→ `l.iter().zip(r).map(..).collect()`（编译器自动 SIMD）；覆盖四则 + 数值比较 + AND/OR 布尔列
- 语义注意：**必须精确复刻 `eval_arith` 语义**（checked 溢出→Null、Int32+Int32 结果类型、数值提升）；新增「新旧路径随机数据等价性测试」兜底
- 文件：`src/executor/expression.rs`（~100 行 + 等价性测试）
- 与 S2 关系：此代码在 S2 后仍服务 Flat fallback 路径，不浪费
- 验证：表达式测试 + 等价性模糊测试 + A-4 bench（当前 0.23x/0.35x）
- 预期：数值表达式 3-8x

### S1.4 Delta 连续 rowid 区间

- 现状：`insert_batch`（delta_store.rs:204）逐条 `row_id_to_idx.insert(rowid, idx)`，rowid 连续
- 改法：新增 `runs: Vec<(u64 base_rowid, usize base_idx, u32 count)>` 有序区间表；`insert_batch` 连续 rowid → 追加一个 run（O(1)）；lookup 二分查 runs 再查 HashMap；**delete 命中 run 中部 → 该 run 拆散回 HashMap**（保删除语义）
- 覆盖：lookup（:144）、delete（:126）、update、all_rows（:303）
- 文件：`src/storage/delta_store.rs`（~50 行）
- 验证：delta/CRUD 测试 + insert 微基准
- 预期：批量 INSERT 20-40%

### S1.5 扫描零克隆

- 现状：`scan_to_chunks_impl` 中 `read_column` → `to_vec()` 整列克隆 + 逐 cell `col[i].clone()`
- 改法：`read_column` 返回 owned `Vec<Value>` 后按 batch `split_off`/`drain` 零克隆直入 `Vector::Flat`
- 文件：`src/storage/table.rs` + `src/storage/column_store.rs`（~30 行）
- 验证：全表扫描测试 + A-1b/c/d bench
- 预期：10-20%（ColumnData 前的过渡收益）

**S1 完成标准**：4-5 个独立 commit，每项全量回归 + A 系列 bench 对比，验收报告更新。

## 四、S2：ColumnData 类型化地基（已确认决策）

### 目标设计

```rust
// 现状（每个值 32B，tag 跳转，无 SIMD）
pub struct ColumnChunk { pub values: Vec<Value>, … }

// 目标（按类型特化，内存连续，可 SIMD）
pub enum ColumnData {
    Int64(Vec<i64>), Int32(Vec<i32>), Float64(Vec<f64>), Float32(Vec<f32>),
    Varchar(/* offset + data 双数组，先 Vec<String> 简化 */),
    Boolean(/* BitVec */), Timestamp(Vec<i64>), Blob, Json, Vector, VectorInt8,
}
// NULL 处理：Nullable(Box<ColumnData>, BitVec) 或 Vector::Typed 侧 Option<BitVec>
```

### 里程碑

| 里程碑 | 内容 | 产出 |
|---|---|---|
| M0 | `ColumnData` 类型 + Value 双向转换 + 等价性测试（不接线） | `src/common/column_data.rs`，~400 行 |
| M1 | 存储层：`ColumnChunk.values` → `Option<ColumnData>`；`read_column` 解压直接产出类型化数组；**序列化字节格式不变**（磁盘兼容，持久化测试护航） | column_store.rs + table.rs |
| M2 | `Vector` 增 `Typed(ColumnData)` variant 双路径并行；表达式类型特化升级（复用 S1.3 代码） | vector.rs + expression.rs |
| M3 | filter/selection 类型化（bool 列直扫）+ sort/aggregate/join 适配 Typed（复用 S1.1/S1.2） | operators/ |
| M4 | 清理 + 基准对比 + 路线图文档更新 | — |

### 语义风险与对策

- **表达式语义复刻**（checked 溢出→Null、跨类型数值提升、三值逻辑、Float to_bits 比较/hash）→ 新旧路径随机数据等价性测试（M0 起持续维护）
- **磁盘格式兼容**：S2 全程保持 `serialize_values` 字节格式不变，旧数据可读
- **公共 API 不动**：`Value` 保留为边界类型（INSERT 输入、SELECT 输出），WAL 格式不动
- **NULL 语义**：现有系统 NULL 显式（`Value::Null`），类型化路径保留三值逻辑

## 五、S3：大数据量质变算法（S2 后）

| 优化项 | 解决什么问题 | 算法参考 | 质变点 |
|---|---|---|---|
| 外排序（External Merge Sort） | 超内存 ORDER BY 崩溃 | DuckDB External Sort | 10GB 数据 + 1GB 内存可排序 |
| Grace / Hybrid Hash Join | 大表 JOIN OOM | PostgreSQL Hybrid Hash Join | 内存占用 O(右表/N) |
| Zone Map（page 级 MinMax） | row group 级 skip 粒度粗 | ClickHouse Mark Index、Parquet Page Index | 跳过粒度细 ~100 倍 |
| Bloom Filter 索引 + Join 下推 | 高基数列等值查询扫太多 RG | RocksDB / DuckDB Bloom Filter | 1000 RG 只读 1-2 个 |
| 延迟物化深化 | 过滤后仍解压非谓词列 | DuckDB Late Materialization | 宽表 I/O 减少 10-50x |
| SIMD 向量化（S2 收益兑现） | Value enum 阻向量化 | DuckDB Vectorized Execution | 百万行以上 4-8x |
