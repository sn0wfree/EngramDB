# EngramDB v0.25 × Agent 记忆调研映射

> 依据：`docs/调研核对-Agent记忆.md`（已核对）· 路线图 `EngramDB 后续路线图 v0.23+.md` §五  
> 定位不变：**底层引擎**，不做 Cognee/Redis Iris 式应用层记忆运营（路线图 §七）

---

## 1. 调研 → 路线图条目

| 调研启示 | 落到 | 动作 | 优先级 |
|---|---|---|---|
| 长期记忆 = 语义召回 + 过滤，不是纯 SQL 点查 | **F2 统一 SEARCH** | 精确 / 向量 / 过滤+向量 三模式 API 定稿 | P0 |
| 多信号召回（语义/时间/实体）优于单向量 | **F1 RRF 算子化** | 现有 `search/hybrid.rs` 纯函数接入执行器；权重可配置 | P0 |
| Session 事件流 + TTL + 摘要列 | **F3 Session 存储约定** | 表约定 + TTL 过期；**摘要生成不进引擎**（调用方负责写 summary 列） | P1 |
| 图遍历/实体关系是关联查询关键 | **F4 分层检索 v2** | 依赖 D1 GraphEngine；v0.25 只留接口，不承诺四图 | P1 |
| 嵌入式「关系+图+向量单事务」是相邻竞品 | **差异化** | EngramDB 强在**列存分析 + 压缩 + 多引擎**；记忆场景补检索入口，不改写引擎内核 | — |
| 托管服务（Iris/阿里云）做抽取与运营 | **明确不做** | 抽取/ETL/晋升/路由留给应用层或 Iris 类服务 | — |
| 信任状态机（confirm 前不可行动） | **缓做** | 可在应用层用 status 列表达；引擎不建 epistemic 模型 | P2+ |

## 2. 建议的 v0.25 交付切片（在原 F1–F4 上收紧）

### F1 · RRF 混合排序算子化（P0，不动存储）
- 输入：向量命中列表 + 结构化过滤命中列表（或两路 ID+score）
- 输出：合并后 top-k DataChunk
- 验收：与 `search::hybrid` 纯函数结果一致的差分测试

### F2 · 统一 SEARCH 入口（P0）
```sql
-- 示意（语法可再定）
SEARCH ON mem
  MODE semantic | exact | hybrid
  QUERY '...' | VECTOR [...]
  FILTER user_id = ? AND updated_at > ?
  LIMIT 5;
```
- 底层复用现有 HNSW + 过滤 +（F1 后）RRF
- 不做查询语言大扩展：优先库 API / 既有 SQL 方言扩展点

### F3 · Session 记忆表约定（P1，schema 约定 + 样例）
| 列 | 说明 |
|---|---|
| session_id / owner_id | 作用域 |
| event_seq / role / content | 有序事件（或外置 blob + 索引） |
| summary | 可空，应用层写入 |
| expires_at | TTL；引擎可提供过期扫描辅助，不强制后台任务 |

- 附 `examples/` 或 docs 可运行约定；**不**内置 LLM 摘要

### F4 · 分层检索接口预留（P1）
- `SearchBackend` trait：`Exact` / `Vector` / `Hybrid` / `Graph`（Graph 可 stub）
- Graph 实现挂到 D1，避免 v0.25 绑死图模型

## 3. 明确不进 v0.25

| 项 | 原因 |
|---|---|
| MemoryETL / 自动抽取 / 记忆晋升 | 应用层 / 托管服务职责 |
| 四张正交图 + RL Memory Manager | 论文未证实；成本高，等 D1 与真实负载 |
| Intent Router / Playbooks / Lens | Iris 平台能力，非嵌入式引擎 |
| epistemic 信任状态机 | 可用普通状态列表达，非引擎内核 |
| 对标 LOCOMO 等基准叙事 | 无一手数据前不写进对外材料 |

---

## 4. 与竞品一句话

- **vs Redis Iris**：Iris 卖托管记忆运营；EngramDB 卖可嵌入的存储与检索底座——F1–F3 是让底座「够用」，不是复刻 Iris。
- **vs contextdb.tech**：同为嵌入式单文件；对方主打图+状态机+同步，EngramDB 主打列存分析压缩——记忆功能是**检索面补齐**，不是改赛道。
- **vs 阿里云 RDS ContextDB**：企业记忆运营 SaaS；EngramDB 不做多租户运营面。

## 5. 建议执行顺序

```
F2 API 草案 → F1 RRF 接执行器 → F3 表约定+测试 → F4 trait 预留
（依赖：向量索引与过滤已具备；F4 图部分跟 D1）
```

退出标准（沿用路线图语气）：F1 差分过、F2 三模式有集成测试、F3 文档+TTL 测试、F4 编译期接口不破兼容。
