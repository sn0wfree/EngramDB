# Phase 1.5 — M04 INSERT...RETURNING

## Summary

Implemented `INSERT...RETURNING` clause, allowing INSERT statements to return the inserted rows' values (including AUTO_INCREMENT-generated IDs) without a separate SELECT.

## Changes

### Parser (`src/sql/parser.rs`)

- Extracts `insert.returning` from sqlparser 0.47's `Insert` AST
- Converts sqlparser `SelectItem` (Wildcard, UnnamedExpr, ExprWithAlias) to our `SelectItem`
- Passes `returning: Option<Vec<SelectItem>>` to `InsertStmt`

### Physical Plan (`src/executor/physical_plan.rs`)

- Added `returning: Option<Vec<crate::sql::ast::SelectItem>>` field to `PhysicalPlan::Insert`

### Planner (`src/sql/planner.rs`)

- `plan_insert` passes `stmt.returning` through to `PhysicalPlan::Insert`

### Executor (`src/executor/executor.rs`)

- On INSERT with RETURNING: records `base_row_id` before insert, then reads actual rows from table via `get_row_by_id`
- `evaluate_returning_expr` evaluates RETURNING expressions against stored rows:
  - `ColumnRef { column }` → looks up column by name in table def
  - `Literal(v)` → returns literal value
  - `Wildcard` → returns all columns
- Returns `QueryResult` with RETURNING columns and values instead of just `rows_inserted`

## Tests

- `test_insert_returning`: Tests RETURNING with single column, multiple columns, and `*` wildcard; verifies AUTO_INCREMENT values are returned correctly
