## 三、架构变更

### 新增/改造
- `src/common/column_data.rs`：`ColumnData { values: ColumnValue, nulls: Option<BitVec> }`
  - ColumnValue 11 种类型化数组（32B enum → 连续数组，Int64 8B/值）
  - 自实现 BitVec（1 bit/row）；try_from_values（纯类型列探测）
  - from_values_typed/serialize_typed/deserialize_typed（磁盘格式兼容）
  - gather（selection 收集）/ take_front（扫描分块）/ append（列合并）
- `src/executor/vector.rs`：`Vector::Typed(ColumnData)`（双路径并行）；get 签名 `&Value` → `Value`
- `src/executor/expression.rs`：eval_typed_binary（Typed×Typed）、eval_typed_constant（Typed×Constant）、boolean_to_selection Typed 直扫
- `src/storage/column_store.rs`：ColumnChunk.values → data: Option<ColumnData>；matches_predicate_typed
- `src/storage/table.rs`：scan 直出 Typed；PREWHERE 类型化直扫；S1.5 drain → take_front
- `src/executor/operators/`：aggregate 数值快路径、hash_join 整数键（inner）、sort 索引排序 + gather

### 磁盘/WAL/API 兼容性
- 磁盘序列化字节格式**零变化**（交叉验证测试）；旧数据文件可读
- WAL 格式、公共 API（Value 边界）不动
- Value 保留为边界类型（INSERT 输入、SELECT 输出）

## 四、修复的既有 bug

1. **value_cmp 缺 Timestamp 分支**（sort.rs + expression.rs）：Timestamp 比较落 `_` 分支 tag 恒等 → 排序/比较失效。修复为 i64 数值语义。
2. **三值逻辑 NULL OR true**：Typed 路径错误合并输入 NULL 位 → NULL OR true = NULL（应为 true）。修复：输出 NULL 只由逐行三值结果决定。
3. **Float32 无 as_f64**（已知限制）：特化路径 fallback 保持原语义（不扩大影响）。

## 五、双路径策略

- 渐进式迁移：Typed 与 Flat 并行，未迁移路径经 get/to_flat 兼容
- 语义等价性由随机数据交叉验证兜底：4000 轮表达式 + 30 轮聚合 + 200 轮谓词 + 20 轮排序 + 300 轮常量 + 800 轮 S1.3
- 混合类型列（Int32+Int64）保持 Flat（Group By/JOIN 变体语义不变）

## 六、剩余项（S3 候选）

- S3：外排序、Grace/Hybrid Hash Join、Zone Map（page 级 MinMax）、Bloom Filter、延迟物化深化
- M3 后续微优化：GROUP BY 路径 accumulate Typed 化（S1.2 整数键已做 hash 层）
- 全 NULL 列 Typed 表示（try_from_values 返回 None；scan 走 from_values_typed 无影响）

## 七、结论

S2 完成：读路径全面类型化，表达式计算 3.69x，PREWHERE 过滤提升 30%。
磁盘兼容零破坏，786 测试全绿。量级收益验证了「Value enum 是最大瓶颈」的判断。
