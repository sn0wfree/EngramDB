## 一、目标与 KPI

### 1.1 阶段目标

完成 Phase 2 推迟的两项关键闭环：

1. **HeatTracker 运行时迁移**：Auto 表根据访问热度自动迁移到 Memory/Columnar/Log
2. **Bloom Filter 列存集成**：列存扫描时按 Bloom Filter 跳读高基数等值谓词

### 1.2 关键 KPI（10 轮 P50）

| KPI | Phase 2 末 | Phase 2.5 目标 |
|---|---|---|
| Auto 表热路径点查 | 1.0× | **≥ 3×**（迁移到 Memory） |
| Auto 表冷路径压缩 | 1.0× | **≥ +30%**（迁移到 Log） |
| Bloom Filter 列存集成跳读 | 1.0× | **≥ 5×**（高基数等值查询） |
| 迁移决策延迟 | N/A | **< 100ms** |
| 迁移过程无锁 | N/A | **零锁竞争** |

## 二、详细排期

### P1: HeatTracker 接入 Connection 层（D1-D3）

**目标**：每次访问表时记录到 HeatTracker，给后续迁移提供数据。

| 任务 | 产出 |
|---|---|
| `Database` 持有 `HeatTracker` | `src/storage/mod.rs` |
| `Connection::execute()` 入口 + 表扫描路径调用 `record_access()` | `src/lib.rs` + `src/executor/operators/table_scan.rs` |
| 3 个集成测试 | `tests/heat_tracker_runtime.rs` |

### P2: 后台迁移线程（D4-D8）

**目标**：单线程 tick（每次 execute 入口调用一次）按 heat + size 决策迁移。

| 任务 | 产出 |
|---|---|
| `tier_migration::tick(db)` 决策函数 | `src/storage/tier_migration.rs` |
| Auto → Memory/Columnar/Log 迁移实现（数据搬迁 + 索引重建） | 同上 |
| 迁移决策日志 | `tests/tier_migration.rs` |
| 迁移过程不阻塞写入（mutex 隔离数据副本） | 同上 |

**风险**：表重建需大量代码（约 1 周），本期只做"标记 + 决策"，实际迁移数据搬运推迟到 Phase 3。

### P3: Bloom Filter 列存集成（D9-D11）

**目标**：列存 RG 完成时同步构建 Bloom Filter，scan 时按 Eq 谓词跳读。

| 任务 | 产出 |
|---|---|
| `ColumnChunk` 持有 `Option<ColumnBloom>` | `src/storage/column_store.rs` |
| `append_columns_inner` 在 RG 完成时构建 Bloom | 同上 |
| `can_skip_predicate` Eq 路径：Bloom 查询 → typed 验证 | 同上 |
| 持久化：Bloom 序列化到 .hdb | `src/storage/file_format.rs` |
| 集成测试 | `tests/bloom_column_store.rs` |

### P4: 综合测试 + Bench + 最终报告（D12-D14）

| 任务 | 产出 |
|---|---|
| 集成测试 1190 + 集成 52 + 新 8 = **1250+ 测试** | `tests/` |
| Bench 对比（Phase 2 末 vs Phase 2.5）：高基数等值查询 | `benches/bloom_integration_bench.rs` |
| 最终报告 `docs/phase2.5-report.md` | docs |
