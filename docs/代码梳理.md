# EngramDB 代码梳理

> 基线：v0.22.4 · 2026-10  
> 范围：`src/` 架构、模块职责、债务与测试面（静态盘点）

---

## 1. 定位与规模

| 项 | 值 |
|---|---|
| 形态 | 嵌入式单文件（`.hdb`）分析型 DB，Rust |
| 卖点 | SQLite 事务语义 + DuckDB 式列存压缩；面向 AI Agent |
| `src/` | 112 文件 · ≈2.8 MB 源码 |
| 测试/基准/示例 | 22 / 29 / 28 · docs 73 篇 |
| 版本特性 | `query-arena`（默认开）、`mmap-read`、`datafusion`（可选） |

---

## 2. 分层架构

```
Connection (lib.rs, Arc<Mutex<Database>> 共享注册表)
    │
    ├─ sql/        解析(sqlparser) → planner → optimizer(RBO+CBO) → plan cache
    ├─ executor/   向量化 DataChunk(1024行) + operators/*
    ├─ txn/        MVCC 快照隔离 · WAL 组提交 · SAVEPOINT · undo-log
    ├─ wal/        预写日志 · 段滚动 · ARIES 恢复
    ├─ storage/    多引擎 Columnar/Memory/Log/Auto
    │              Delta(行) → Column(列+压缩) · 索引 · mmap · 分层迁移
    ├─ search/     倒排 / BM25 / 模糊 / RRF 混合（多为纯函数，未算子化）
    ├─ common/     类型 · 错误 · 配置 · tokenizer · 内存池
    └─ datafusion_ext/  TableProvider（feature 门控，谓词下推未接）
```

写路径：`INSERT → insert_batcher → Delta → compact → Column + 压缩`；  
读路径：`plan → filter/projection 下推 → table_scan(+skip/bloom) → 向量化算子`。

## 3. 模块速览

| 模块 | 关键文件（大→小） | 职责 |
|---|---|---|
| executor | `expression.rs` 245KB · `executor.rs` · `operators/{aggregate,insert,hash_join,window}` | 表达式求值、算子、向量化执行 |
| sql | `planner.rs` 196KB · `optimizer.rs` · `parser.rs` · `cost_model` | 规划/优化/解析 |
| storage | `table.rs` · `mod.rs` · `column_store.rs` · `compression/*` · `index/*` | 表、列存、8+ 压缩、6 类索引、mmap |
| txn | `manager.rs` · `mvcc.rs` | 事务与并发控制 |
| wal | `mod.rs` · `writer` · `recovery` · `reader` | 日志、组提交、恢复 |
| search | `sparse` · `bm25` · `fuzzy` · `hybrid` | 检索原语 |
| common | `column_data` · `tokenizer` · `types` · `config` | 基础设施 |

`lib.rs`（186KB）是门面：`Connection` / `PreparedStatement` / API 聚合——多连接已走全局 path 注册表共享 `Database`（A5c），内部仍是 Mutex 串行。

## 4. 测试与质量闸门

- **差分 SQLite**（`tests/differential_sqlite.rs`）：DML、JOIN、窗口、CAST、CASE、UNION 等持续扩面（B4）。
- **语义闸门**：`phase0_semantic_gate.rs`（DEFAULT/FK 等七项已绿）。
- **并发**：`a5_concurrency.rs` 16 线程无丢写；回滚 `migration_mvcc` 等。
- **崩溃/持久化**：`inject_crash_*`、`mmap_persist`、`group_commit_*`。
- **bench**：criterion + 自带 main 双轨；统一报告仍是缺口（B3）。

## 5. 债务快照（详见 `docs/历史包袱清单.md`）

| 优先级 | 未清项 |
|---|---|
| P0 | 列存 DELETE 仅 Delta 可删（需 tombstone+compact）；文件头原子性部分场景未在可编译环境复验 |
| P1 | ReadUncommitted/Serializable 未实现；DataFusion 下推未接；PREWHERE 简化版；LogEngine 无 UPDATE/DELETE |
| P2 | `buffer_pool.rs` 已 deprecated 待删；docs 73 篇可归档；大文件 `expression/planner/lib` 待拆 |

近期已清：WAL 段滚动、Varchar 双数组、HAVING/聚合投影、FK、Phase0 语义闸门。

## 6. 路线图锚点（v0.23+）

`v0.23 正确性/性能 → v0.24 DataPoint/Graph → v0.25 Agent 记忆 → v0.26 生态`  
当前工作区提交停在 A5 多连接 / A4 undo-log / B1 Varchar / Phase0 闸门一线。

---

## 7. 一句话结论

分层清晰、测试密度高、性能路径打磨深的**原型级分析库**；最大结构性风险是 `lib.rs`/`planner`/`expression` 三个超大文件与“Mutex 单写多读”并发模型，最大正确性残留是列存删除与差分/崩溃自动化覆盖面。
