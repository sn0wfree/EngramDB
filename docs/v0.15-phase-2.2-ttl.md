# Phase 2.2 — Ag01 内置 TTL（表级自动过期）

## Summary

实现了表级 TTL（Time-To-Live）功能。设置了 TTL 的表，数据在超过指定秒数后自动过期——读取时被过滤（惰性过期），compaction 时被物理删除（空间回收）。

## 设计思路

采用 RocksDB 风格 + 惰性过滤的混合策略：
- **写入时**：自动填充 `Timestamp` 列（如果用户未提供值）
- **读取时**：`get_row_by_id()` 和 `scan()` 检查 `created_at + ttl < now()`，过期行视为不存在
- **Compaction 时**：`compact_delta()` 过滤掉过期行，仅将未过期的行写入列存
- **持久化**：TTL 配置存于 `TableDef`，通过 `CatalogSnapshot` 序列化/反序列化

## Changes

### Schema (`src/common/types.rs`)

- `TableDef` 新增字段：
  - `ttl_seconds: Option<u64>` — TTL 秒数，`None` 表示永不过期
  - `ttl_column: Option<usize>` — TTL 参考列索引（必须是 `Timestamp` 类型）
- `TableDef::new()` 初始化两个字段为 `None`
- `has_ttl()` / `ttl()` / `is_expired(row)` 辅助方法

### 写入路径 (`src/storage/table.rs`)

- `insert()`: AUTO_INCREMENT 之后、NOT NULL 检查之前，自动填充 `ttl_column` 为当前时间戳（如果值为 Null 或空）
- `insert_row()`: 同理，在写入 Delta 层之前自动填充

### 读取路径（惰性过滤）

- `get_row_by_id()`: 读取行后，调用 `self.def.is_expired(&row)` 检查，过期则返回 `None`
- `scan()`: 遍历列存和 Delta 层时，跳过过期行

### Compaction 路径（物理删除）

- `compact_delta()`: 如果表有 TTL，遍历 Delta 层所有行，仅将未过期的行 transposed 写入列存
- 新增 `transpose_rows()` 辅助函数：行列表 → 列式格式

## Test

- `test_ttl_expiration`: 建表（TTL=60s）→ 插入 → 验证可查询 → 模拟过期时间 → 验证不可查询 → compaction → 验证新数据正常
